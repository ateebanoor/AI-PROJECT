# Snake AI: BFS vs A* vs Genetic Algorithm

Three snakes play classic Snake on a 10x10 board: one finds food with **BFS**, one with **A\***, and one follows a simple decision rule whose four weights are **evolved by a genetic algorithm**. They are compared on 100 identical games by average score, survival time and search effort. The project shows why a heuristic makes search cheaper, how a snake that only chases food eventually traps itself, and how evolution finds a rule that keeps more room to live.

## Run

Always run from the repository root.

| What | Command |
|---|---|
| Menu (watch a snake, train the GA, quick console comparison) | `python src/main.py` |
| **Reproduce all experiments** (trains the GA, 100 test games, table + 6 charts, about 4-5 minutes) | `python src/experiment.py` |
| Unit tests | `python -m unittest discover tests` |

The experiment is fully seeded: the same numbers appear on every run. Results are written to `outputs/results/` and charts to `outputs/figures/`.

## Features

- Snake game built from OOP classes (`Snake`, `SnakeGame`, `Agent` and subclasses)
- BFS and A* written from scratch, with node counts, path and cost
- GA snake that evolves the weights of a four-feature decision rule
- Fitness-per-generation chart and a table of average score and survival time
- Optional Pygame window to watch any snake play

## Known limitations

- Fixed 10x10 board; the 100-move starvation rule is part of the game.
- BFS and A* re-plan every move and treat the body as a fixed wall, so they cannot see that a path may trap them.
- The GA is run once (one seed) and trained on only 5 games; the variation between GA runs is not measured.
- The GA's "space" feature (flood fill) is written by us; the GA only learns how much to trust it.
- Deep learning, paid APIs and deployment are out of scope.

## Data

No external dataset is used. All games are generated by `src/game.py` from integer seeds.
